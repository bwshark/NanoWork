### 真机脚本踩的坑（下次直接套）
1. **`node_modules/.vite/deps_temp_*` 必须先移走**：渲染层新增/改 `@mui/icons-material` 图标 → vite 重新优化依赖 →
   要删 `deps_temp_*` → 撞安全删除守卫（count 2400+ > threshold 50）→ **dev server 直接崩**。
   启动前 `mv node_modules/.vite/deps_temp_* /tmp/`，dev server 就正常了（新 temp 目录 vite 自己建、不删）。
2. 切场景**每个场景开新 page**：store 是模块级单例、展开态是组件 state，一次 goto（同 URL / about:blank / 加 query）
   都验证过复位不了 → 上一个场景的「同步中」按钮还挡在下个场景身上。
3. 桩数据落 **localStorage 且同时 `Object.assign` 内存 `window.__PM__`**：只落盘的话当前页面点的按钮拿到的是上轮桩；
   `sessionStorage` 不跨 tab（新 page 读不到），`localStorage` 才跨。脚本开头清一次 localStorage。
4. `platform.pluginsMarkets()` 返回 `{ markets, error }`，**不是裸数组**——给裸数组会被当空注册表（静默）。
5. 桥桩里的 `manifest.permissions` 必须给 `{ tools: [], network: [] }`：缺子字段 → `PluginsPage` 里
   `permissions.tools.length` 抛错、整块 UI 崩溃（主进程侧 `asStringArray` 总会兜底，桩数据要照它的形状造）。
6. 插件激活态是**引擎上报**的，不由 `scanPlugins` 决定（引擎不可达 → 芯片「状态未知」）。
   「安装 ≠ 启用」要验的是启用开关（Switch）仍为 off + 没有「已启用但引擎未激活」漂移提示。
7. disabled 的 MUI Button，Tooltip 的 `title`/`aria-label` 落在**包裹 span** 上 → 断言要 hover（force）读
   `.MuiTooltip-tooltip`，或读 span 的 aria-label。
