## FR-2.4 路径② 收尾：生产接线测试 + 真机端到端

前提：第 1 步（成员派发）、第 2 步（引擎编排调度）、第 3 步（成员归属 UI）**此前已落地并提交**，
但两边的**测试都只覆盖各自一侧**，且从未连起来跑过一次。这一轮补的就是这两件事。

### 一、生产接线从没被测过（本轮最大的缺口）

- `tests/agent/test_expert_group.py` 的 `run_member` 是**注入的假函数** → 它只能证明
  「编排按预期顺序跑完」，证明不了「成员的人设 / 工具策略 / 模型真的到了子代理手上」。
- 而这三项脱钩后**一条报错都不会触发**：编排照样跑完、事件照样发、`final_text` 照样有内容，
  唯一现象是「成员答得像个通才」。FR-2.3 时代「专家 `systemPrompt` 只被解析、从未使用」
  就是这个形状。
- **根因的可测性问题**：`_run_member` 原本是 `_maybe_run_expert_group` **内部的闭包**
  → 这段逻辑永远测不到。提成工厂方法 `AgentLoop._make_member_runner(...)`（带显式上下文参数）。
- 新增 `tests/agent/test_expert_group_wiring.py` **13 例**：驱动**真的 `SubagentManager`**
  断言子代理行为（tool 被拒/放行、system message 含人设、告警含具体成员与模型名）。
- AgentLoop 上有一批**只读 property**（`model_presets` 派生自 `runtime_resolver`）不能 `setattr`；
  因此用 `AgentLoop.__new__` + 只写可写槽位（`_member_runtime` 里的 `getattr(..., None)`
  正好让未设置的场合自然走「无 resolver」分支）。

### 二、两条变异之外的意外收获

1. **同一项目两套 logger**：先是自己把 4 处 loguru 日志写成 `%s`（占位符不替换 → 成员模型
   失败告警看不到任何具体值）；随后「统一改成 `{}`」又踩另一头——`expert_group.py` 用的是
   **标准 logging**，改动当时就让 3 例既有测试炸 `TypeError: not all arguments converted`。
   → `loop.py` 用 `{}`、`expert_group.py` 用 `%s`。AST 全仓扫描另发现 2 处既有违规
   （`agent/tools/loader.py:109/114`，工具名冲突告警看不到是哪个工具）已顺手修。
   → 加守卫 `tests/test_log_placeholder_contract.py`（AST 扫描，排除 `.venv`；`{}` 识别要避开
   `{%d}` 这种第三方字面花括号）。**这类错误两种写法都「看起来没事」，只能靠机器拦。**
2. **成员模型未命中预设时会被裸名透传给 provider**：真机日志
   `Response: Error: The model 'ghost-preset-nonexistent' does not exist`
   —— 一个成员的模型名写错会把**整个专家团**打成失败。修为「目录非空且未命中 → 退回本轮
   runtime 并告警」；**目录为空仍允许透传**（没配预设 ≠ 全部失效，否则自定义模型永不生效）。

### 三、真机验证（第一次真正打通）

`nanobot serve --port 18997 --verbose` + 两条成员的 sequential 请求，日志：

```
WARNING | expert group member 'probe-member': model '...' is not a configured preset; using turn runtime
INFO    | Running inline subagent [6da7e6b4]: expert-group:探针     ← 成员 1
INFO    | Running inline subagent [25f719aa]: expert-group:财务     ← 成员 2
INFO    | Running inline subagent [c4757fe9]: expert-group:探针     ← lead 收口（aggregate=lead）
```

三条形状校验（非法 mode / 空成员 / lead 不在成员里）真机均 **400 带明确原因**。
⚠️ provider 账户配额耗尽（`out of quota`），**带真实 LLM 输出的整轮跑通仍未验证**。

### 坑记

- **查 loguru 日志：`caplog`（标准 logging）和 `capsys` 都拿不到** —— 只能临时
  `logger.add(callable_sink)` 并在 fixture 里 `remove`。
- 网关起临时实例用**新端口**（18997/18998/18999），不去动常驻的 `:18900`；
  Python 进程不热重载，改源码必须重启才生效。
- 用 MagicMock 冒充 AgentLoop 的依赖时，**别给它设 `model_presets`**（只读 property，会 AttributeError）；
  它是从 `runtime_resolver.model_presets` 派生的，设 resolver 即可。
