# ADR-0005：删除类操作改道回收站 + fail-closed

| 项 | 值 |
|---|---|
| **状态** | 新建 |
| **实现核对** | ✅ 已落地 |

| **相关章节** | v2 第 6 章（FR-8.3）；v2 第 11 章（工具网关） |
| **v2 原文表述** | 删除类操作改道回收站 + fail-closed |

## 决策

**删除类操作一律改道系统回收站；回收站不可用即 fail-closed（拒绝执行而非直删）。**

`delete_file` 是唯一删除入口；同时设批量删除守卫与删除留痕。

## 背景

删除不可逆。LLM 的删除意图一旦误判，用户资产直接消失，且事后无法追责。

## 后果

- **正面**：提示词被绕过也不会丢数据；删除可追溯。
- **代价**：需处理「回收站不可用」的降级语义（选择 fail-closed 而非静默直删，可能让某些环境下的删除能力不可用——这是有意的取舍）。
- **落点**：引擎 `nanobot/security/trash.py`、`nanobot/agent/tools/filesystem.py`（`delete_file` / 批量守卫 / 留痕，`[LOCAL PATCH]` FR-8.3）。
