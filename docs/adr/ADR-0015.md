# ADR-0015：扩展分发做成「对象存储 + 索引 json」

| 项 | 值 |
|---|---|
| **状态** | 新建 |
| **实现核对** | ⏳ 设计态（V1 未开工，对应 FR-3.7 / FR-3.8） |
| **决策日期** | 2026-09-17（自 `docs/nanowork-prd-design-v2.md` 第 23 章迁入） |
| **相关章节** | v2 第 12.5 节（市场四档来源）；v2 第 12.6 节（版本隔离缓存）；v2 第 6 章（FR-3.7 / FR-3.8） |
| **v2 原文表述** | 扩展分发做成「对象存储 + 索引 json」，不做应用服务 |

## 决策

**扩展分发做成「对象存储 + 索引 json」，不做应用服务。**

构建期生成 `index.json` 与签名、上传后运行时零计算。
代价是包对象**必须不可变**（配合版本隔离缓存）。

## 背景

技能/插件/连接器/专家的市场分发，可以做成一个带 API 的应用服务，
也可以做成静态对象 + 索引文件。

## 后果

- **正面**：零应用服务器成本；分发是纯静态读。
- **代价**：包对象必须不可变——同一版本号不允许覆盖发布，否则客户端版本隔离缓存会失效。
- **实现状态**：V1 未开工。v2 第 12.6 节的「版本化缓存」与「版本锁定写入」同样未做，属 `FR-3.7` / `FR-3.8`（M3 的 4/6 缺口）。
