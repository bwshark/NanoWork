| 项 | 值 |
|---|---|
| **状态** | 新建 |
| **实现核对** | 🟡 部分落地（存在 channelScan 例外，已由 CI 棘轮固化） |
| **决策日期** | 2026-09-17（自 `docs/nanowork-prd-design-v2.md` 第 23 章迁入） |
| **相关章节** | v2 第 8.2.1 节；v2 第 8.4.1 节 |
| **v2 原文表述** | `src/ai/runtime/nanobotHttp/**` 是**唯一**允许知道引擎 wire 格式的位置；渲染层只允许 import `@/ai/runtime`（及其 `./types`） |

## 决策

**`src/ai/runtime/nanobotHttp/**` 是唯一允许知道引擎 wire 格式的位置；
渲染层只允许 import `@/ai/runtime`（及其 `./types`）。**

`session_id` / `access_mode` / `mcpServers` / `jobs.json` / `delta.nanobot_event`
只允许出现在该目录内；契约层不出现任何引擎特有字段；
`ChatHandle` 等 transport 原语不上浮。

## 背景

ADR-002 定了防腐层，但「什么算泄漏」需要一条可机械检查的边界，
否则防腐层会退化成口号：字段名一处一处漏出来，升级时到处改。

## 后果

- **正面**：把「防腐层」从口号变成可检查的边界；引擎升级的面收敛到一个目录。
- **代价**：新增引擎交互需先扩契约层，不能就近写在页面里。
- **⚠️ 实现核对（2026-09-17）**：存在例外——`src/lib/channelScan.ts`（多处 `session_id`）与 `src/types/channel.ts:68`。它们走的是 `settings.channel.connect.*` 认证 WebSocket 帧，是与 `/v1/chat/completions` **并列的另一条引擎协议**，尚未收进 runtime 层。已固化为 CI 检查（`platform-boundary` 作业第二段），两文件登记为基线例外。另 `src/ai/runtime/types.ts` 中出现的 `session_id` 仅为注释里的反例说明，非泄漏。
