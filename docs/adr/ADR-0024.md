## 决策

**执行模式与计划提交都落在引擎会话作用域内：**

- 模式是与 `access_mode` / `tool_approval` 并列的**第四根轴**（`WorkspaceScope.session_mode`），**未知取值报错不降级**。
- 模式禁止由 `SessionModeHook` 在 `before_execute_tool` **deny** 并回注工具结果。
- **计划经 `submit_plan` 工具通道提交**：引擎截获后不下发工具系统，转成 `kind=plan` SSE 事件；用户裁决作为**下一轮用户消息**回来。
- Plan 模式下批准动作顺带切回 Craft（否则批准的语义是空的）。

## 背景

执行模式（`ask` / `plan` / `craft`）若只写在客户端或提示词里，同样拦不住引擎进程内的工具执行（理由同 ADR-021）。
计划提交若靠「解析模型最终回答」，则 LLM 输出结构不可靠。

## 后果

- **正面**：模式在真正执行工具的地方强制；计划有 schema 校验、可拒绝重来；「当时批准了什么」在会话历史里可追溯。
- **代价**：模式/计划的两端新增字段都属 LOCAL PATCH（上游合并需重打）；客户端在 `capabilities.executionModes` 缺省时**隐藏**模式选择器（不留点了不生效的开关）。
- **落点**：引擎 `nanobot/agent/hooks/session_mode.py`、`nanobot/security/tool_approval.py`（`session_mode_forbids_tool`）、`nanobot/agent/tools/plan.py`、`nanobot/security/workspace_access.py`（`_normalize_session_mode` 抛 `WorkspaceScopeError`）、`nanobot/utils/progress_events.py`；客户端模式选择器 + `session-start` / `mode-change` 事件。
