# ADR-0019：渲染层持久化改为「一 key 一文件 + 按 key 路由归属」

| 项 | 值 |
|---|---|
| **状态** | 新建 |
| **实现核对** | ✅ 已落地 |
| **决策日期** | 2026-09-17（自 `docs/nanowork-prd-design-v2.md` 第 23 章迁入） |
| **相关章节** | v2 第 18.2.5 节；v2 第 18.2.3 节（三原则之 1） |
| **v2 原文表述** | 渲染层持久化改为「一 key 一文件 + 按 key 路由归属」，落点表收口在纯模块 `electron/storageRoutes.ts` |

## 决策

**渲染层持久化改为「一 key 一文件 + 按 key 路由归属」。**

落点表收口在纯模块 `electron/storageRoutes.ts`（无 IO，可单测：
路由归属 / 路径越界 / 编解码往返）。过渡落点 `sessions` / `tasks` / `artifacts`
留在 ②，待 D2 实体化消化。

## 背景

原实现把所有 key 塞进 ② 的单个 JSON blob：每次写入都要重写全量（写放大），
且「卸载丢用户资产」与「同步无法按实体读写」两个问题同时存在。

## 后果

- **正面**：消除写放大与「卸载丢用户资产」；纯模块可单测。
- **代价**：需维护一份落点表，新 key 必须登记归属，否则写到哪里不确定。
- **落点**：`electron/storageRoutes.ts`、`src/platform/storage.electron.ts`。
