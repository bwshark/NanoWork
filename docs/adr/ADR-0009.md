# ADR-0009：渠道抽象为 ChannelDescriptor

| 项 | 值 |
|---|---|
| **状态** | 新建 |
| **实现核对** | 🟡 部分落地 |
| **决策日期** | 2026-09-17（自 `docs/nanowork-prd-design-v2.md` 第 23 章迁入） |
| **相关章节** | v2 第 16 章（IM）；v2 第 6 章（FR-6.3） |
| **v2 原文表述** | 渠道抽象为 ChannelDescriptor |

## 决策

**渠道抽象为 `ChannelDescriptor`：新增渠道只加一个声明。**

渠道的元数据（名称、字段、能力、接入方式）集中声明，
UI 与同步链路按声明渲染，不写渠道专属分支。

## 背景

IM 渠道各有各的字段与接入流程。若每个渠道写一套 UI 分支，新增渠道即改多处。

## 后果

- **正面**：新增渠道只加一个声明。
- **代价**：声明需与引擎侧 `channels/<name>/manifest.py` 的 `SETUP_SPEC` 保持对齐（两份声明，靠约定同步）。
- **落点**：`src/lib/channelMeta.ts` + `src/types/channel.ts`（**已落 5 个渠道**：钉钉 / 飞书 / Lark / 微信 / 企业微信，其中飞书 / Lark / 微信支持扫码接入）、`src/lib/channelScan.ts` + `components/im/ChannelScanPanel.tsx`；引擎侧 `nanobot/channels/<name>/manifest.py`。**未做**：引擎侧 IM 结果回推（对应 v2 `FR-6.3`）。
