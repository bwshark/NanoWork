# ADR-0006：V1 实体即带 SyncMeta

| 项 | 值 |
|---|---|

| **实现核对** | ⬜ 未落地（仅类型声明，无写入点） |

## 决策

**V1 的数据实体即携带 `SyncMeta`：V1.5 上线同步零迁移。**

实体在写入时带上 `updatedAt` / `updatedBy` / `rev` / `deletedAt` 等元信息，
即使 V1 阶段没有任何同步逻辑消费它们。

## 背景

V1.5 要做跨端双向同步（LWW + tombstone），同步需要每个实体携带
「最后修改时间 / 修改者 / 删除标记」。若 V1 不落字段，V1.5 需对既有数据做迁移。

## 后果

- **正面**：V1.5 上线同步零迁移，省掉一次全量数据改写。
- **代价**：每个实体写入路径都要额外维护元信息。
- **⚠️ 实现核对（2026-09-17）**：**本条未落地。** `src/types/event.ts` 只有 `SyncMeta` 的**类型声明**，全仓无写入点（grep `SyncMeta|syncMeta|updatedBy|deletedAt` 无生产者）。v2 第 19.2 节明确要求「V1 必须先落 `SyncMeta`」，现在补 4 个字段的成本远低于 V1.5 返工。**属当前最高优先级的遗留风险之一。**
