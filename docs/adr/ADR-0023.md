# ADR-0023：会话视图有两个产地（实时增量 / 批量重放）

| 项 | 值 |
|---|---|
| **状态** | 新建 |
| **实现核对** | ✅ 已落地 |
| **决策日期** | 2026-09-17（自 `docs/nanowork-prd-design-v2.md` 第 23 章迁入） |
| **相关章节** | v2 第 9.6 节 |
| **v2 原文表述** | 会话视图有**两个产地**（实时增量 / 批量重放），二者必须**同源**：事件在调用方栈上同步构造、内存视图与磁盘事件消费**同一批事件对象**；视图侧的派生值（消息 `createdAt`、权限日志 `id`/`at`、产物 `createdAt`）一律取自事件而非各自 `nowIso()`/`genId()` |

## 决策

**两个产地必须同源：**

- 事件在调用方栈上**同步构造**；内存视图与磁盘事件消费**同一批事件对象**。
- 视图侧的派生值（消息 `createdAt`、权限日志 `id` / `at`、产物 `createdAt`）**一律取自事件**，而非各自 `nowIso()` / `genId()`。
- 约束方式：把不变量写成可执行测试 `tests/events/equivalence.test.ts`（用 store 的真实动作跑完一轮会话再投影比对，逐字段钉死）。

配套约定：`messages` 只取活跃时间线（DAG 回溯 `activePath`）；`permissionLog` 取**全量**事件（审计 append-only）。

## 背景

会话视图有两个产地：会话进行中的**实时增量**，与刷新后的**批量重放**（投影事件流）。
两条路径各自生成时间戳 / ID，必然漂移，症状是「刷新前 / 刷新后不一样」且极难追查。

## 后果

- **正面**：消除最难查的一类不一致；视图正确性有了可执行的判据。
- **代价**：新增视图侧字段时必须从事件取值，不能就近 `new Date()`；漏记事件时 `recordFor` 上报而非静默（内存视图仍为本次会话权威）。
- **落点**：`tests/events/equivalence.test.ts`、`src/events/`、`src/stores/sessionsStore.ts`。
