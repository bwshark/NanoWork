# ADR-0001：引擎以独立进程接入

| 项 | 值 |
|---|---|
| **状态** | 采纳（现状） |
| **实现核对** | ✅ 已落地 |
| **决策日期** | 2026-09-17（自 `docs/nanowork-prd-design-v2.md` 第 23 章迁入） |
| **相关章节** | v2 第 7 章（五层架构）；v2 第 8 章（引擎契约层） |
| **v2 原文表述** | 引擎以独立进程接入，不走 in-process 依赖 |

## 决策

**引擎以独立进程接入，不走 in-process 依赖。**

客户端只经引擎的 OpenAI 兼容 HTTP/SSE 接口（`/v1/chat/completions` 等）与它交互，
不 import 引擎代码、不共享内存、不依赖引擎内部对象。

## 背景

候选方案是把 nanobot 作为 Python 依赖直接 import 进客户端进程（in-process），
或把引擎跑成独立进程、客户端只经网络协议访问。

in-process 的好处是零 IPC 成本、可直接复用引擎对象；代价是引擎崩溃即拖垮整个
客户端、引擎升级需连带重建客户端、且渲染层与 Py 运行时绑死无法跨端。

## 后果

- **正面**：崩溃隔离（引擎挂了客户端仍在，可重连）；引擎可独立升级，客户端不必重打包；Web 端与桌面端可用同一套协议接入。
- **代价**：需要一层契约/防腐层（→ ADR-002）；跨进程带来「客户端无法直接拦停引擎进程内的工具执行」这一结构性事实（→ ADR-021 的直接动因）。
- **落点**：`electron/main.ts` 的 `startNanobot` 拉起 `nanobot serve`；渲染层经 `src/ai/runtime/` 访问。
