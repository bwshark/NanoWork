# ADR-0013：云侧系统边界由三条硬判据决定

| 项 | 值 |
|---|---|
| **状态** | 新建 |
| **实现核对** | ⏳ 设计态（V1.5） |
| **决策日期** | 2026-09-17（自 `docs/nanowork-prd-design-v2.md` 第 23 章迁入） |
| **相关章节** | v2 第 2.5.2 节 |
| **v2 原文表述** | 云侧系统边界由三条硬判据决定（公网回调 / 服务端持密钥 / 关机仍运行） |

## 决策

**云侧系统边界由三条硬判据决定：需要公网回调 / 需要服务端持密钥 / 关机后仍需运行。**

三条命中其一才允许上云；都不命中即留在客户端本地。

## 背景

「哪些逻辑该放服务端」在迭代中极易失控：既容易把服务端逻辑塞进客户端，
也容易为了一点点需求就切微服务。

## 后果

- **正面**：既防「服务端逻辑塞进客户端」，也防过早微服务化。判据可机械执行，不需要每次争论。
- **代价**：判据是必要条件不是充分条件，边界争议仍需 ADR 裁决。
- **落点**：v2 第 2.5.2 节给出 7 个需新增系统的判定与三条硬判据的对照。
