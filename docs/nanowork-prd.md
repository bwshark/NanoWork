# 基于 nanobot 引擎的智能办公软件需求方案

> ⚠️ **阶段受限（V3 需求来源，非当前交付依据）**：本文定位为**企业平台**（代号 WorkPilot：多租户、组织/RBAC、SSO/OIDC/LDAP、审批流、审计、计费、技能市场、项目空间、自建沙箱执行器），与当前 V1「本地优先客户端」的代码基线**不冲突但不同期**。分期口径见 `nanowork-prd-design-v2.md` 第 2.3 节（V1 工作台成型 → V1.5 多端一致 → V2 团队协作 → **V3 企业私有化**）。本文件是 **V3 阶段的唯一需求来源**，V1 实现请勿以本文为依据。状态：现行（阶段受限）。

## 0. 背景与结论回顾

nanobot 提供 Agent 内核（多渠道接入、工具调用、Dream 记忆、Cron 调度、MCP 扩展、模型路由、OpenAI 兼容 API），而 WorkBuddy 这类产品的护城河在企业层：组织权限、安全审计、协作共享、SLA 运维、产品化 UI。WorkBuddy 已验证的核心形态包括：Ask / Plan / Craft 三种执行模式、专家/专家团/项目空间/人机双写、2 万+ 技能包与 MCP 生态、微信远程派活与定时跑报表。

**本方案的定位**：做一个可私有化交付、引擎可控（MIT）的智能办公 Agent 平台——产品上对标 WorkBuddy，交付形态上避开 SaaS 红海，主攻"企业私有化 POC + 中小团队内部助手"两个市场。

## 2. 总体架构

```
┌─────────────────────────────────────────────────────────┐
│  接入层   Web 工作台 │ 企微/微信 │ 飞书 │ 钉钉 │ Slack │ API  │
├─────────────────────────────────────────────────────────┤
│  企业管理层（自建，本方案核心增量）                        │
│  租户/组织/RBAC │ SSO │ 审批流 │ 审计 │ 计费 │ 技能市场 │  │
│  项目空间 │ 知识库管理 │ 管理后台                            │
├─────────────────────────────────────────────────────────┤
│  Agent 引擎层（nanobot，作为依赖引入，不 fork 主干）       │
│  Agent Loop │ 15+ IM Channel │ 工具系统 │ Dream 记忆       │
│  Cron 调度 │ MCP Client │ 模型路由 │ 子 Agent 委派          │
├─────────────────────────────────────────────────────────┤
│  执行环境层（自建，安全关键）                              │
│  沙箱执行器（一次性容器/gVisor）│ 文件工作区 │ 连接器网关     │
├─────────────────────────────────────────────────────────┤
│  数据层  PostgreSQL │ 对象存储 │ 向量库 │ Redis │ 审计日志   │
└─────────────────────────────────────────────────────────┘
```

**关键架构决策：**

1. **nanobot 以 Python 依赖方式引入**，通过其 OpenAI 兼容 API / Python SDK 对接。禁止 fork 主干改内核——社区自己也在强调核心需要抽象和稳定，跟版合并成本极高。自定义能力全部走它的 Skill / MCP / Channel 扩展点。
2. **沙箱必须自建**。nanobot 内置 shell、文件读写工具，直接进企业环境不可接受。所有"执行类"任务（Craft 模式）路由到隔离执行器：一次性容器（gVisor/Firecracker 级别隔离）+ 租户级网络策略 + 只读挂载企业数据源。
3. **nanobot 单实例 → 平台多租户**：引擎之上套一个"Agent 实例编排层"，每个租户/部门/专家对应一个逻辑 Agent 实例（独立记忆命名空间、独立工具白名单、独立模型配置）。

## 3. 功能需求

### M0 平台底座（P0，一切的前提）

| 编号 | 需求 | 说明 |
|---|---|---|
| F0.1 | 多租户 | 租户数据完全隔离（库/Schema 级），支持私有化单租户模式（大客户可关租户层） |
| F0.2 | 组织架构 | 部门树、用户、角色（RBAC：普通成员/部门管理员/租户管理员/平台运营） |
| F0.3 | 认证与 SSO | 企微/飞书/钉钉扫码登录、OIDC、LDAP/AD 集成 |
| F0.4 | 审计日志 | 全量操作留痕：谁、何时、对哪个 Agent、下了什么指令、执行了什么工具、触达了什么数据，留存 ≥180 天 |
| F0.5 | 模型配置 | 租户级模型接入（DeepSeek/Qwen/Kimi/GLM/MiniMax/vLLM 私有模型），密钥由管理员统管，终端用户不可见 |

### M1 任务中心（P0，对标 WorkBuddy 核心体验）

| 编号 | 需求 | 说明 |
|---|---|---|
| F1.1 | 三种执行模式 | Ask（仅问答）/ Plan（出方案人审后执行）/ Craft（直接执行） |
| F1.2 | 任务全生命周期 | 自然语言下单 → 任务拆解可视化（步骤树）→ 执行 → 产物交付 → 人工验收/打回重做 |
| F1.3 | 长任务与断点续跑 | 长任务异步化（任务队列），支持中断恢复、失败重试；运行状态可实时订阅推送到 IM |
| F1.4 | 产物管理 | 文档/表格/PPT/图表统一产物库，支持版本、回退、导出（对接企业已有文档系统，不自研编辑器） |
| F1.5 | 人机双写 | 产物在 Web 工作台内可圈选局部让 AI 改写，改动留版本记录（V1.1） |
| F1.6 | 手机远程派活 | IM 渠道发指令 → 云端任务 → 结果回推 IM（复用 nanobot Channel 层） |

### M2 专家与技能市场（P0/P1，对标"专家/专家团"）

| 编号 | 需求 | 优先级 |
|---|---|---|
| F2.1 | 专家（Expert） | = 固化提示词 + 绑定知识库 + 绑定工具白名单 + 绑定模型的逻辑 Agent 实例；内置招聘/法务/投研/财务等模板 |
| F2.2 | 技能（Skill） | 打包格式兼容 nanobot Skill 规范 + MCP Server，支持安装/升级/卸载/版本锁定 |
| F2.3 | 组织级资产沉淀 | 管理员可把个人 Skill/专家/提示词模板发布为组织资产，全员可用；这是对抗"员工离职带走经验"的核心卖点 |
| F2.4 | 专家团 | 多专家协同编排一个复杂任务（子 Agent 委派，V1.1） |

### M3 知识与记忆（P0/P1）

| 编号 | 需求 | 说明 |
|---|---|---|
| F3.1 | 组织知识库 | 文档上传（Office/PDF/图片）、解析、RAG 检索；按部门/角色设访问范围 |
| F3.2 | 记忆租户化 | 复用 nanobot Dream 双阶段记忆，但命名空间按租户+用户隔离，支持记忆查看/编辑/删除（合规要求） |
| F3.3 | 记忆分级 | 个人记忆 / 项目记忆（项目空间内共享）/ 组织记忆（管理员注入，如公司制度） |

### M4 自动化与定时任务（P1，对标"定时跑报表"）

| 编号 | 需求 | 说明 |
|---|---|---|
| F4.1 | 定时任务模板 | 日报周报汇总、竞品监控、数据抓取、定时报表推送，Cron 表达式 + 自然语言双配置 |
| F4.2 | 触发器扩展 | 定时之外支持 Webhook / 邮件触发（V1.2） |

### M5 安全与审批（P0，企业准入门槛）

| 编号 | 需求 | 说明 |
|---|---|---|
| F5.1 | 工具白名单 | 每个专家/角色可使用的工具集显式声明，默认最小权限 |
| F5.2 | 敏感操作审批 | 外发邮件/消息、删除文件、访问敏感目录、超额度 API 调用等动作 → 人在 IM 里一键审批后才能继续执行 |
| F5.3 | 沙箱执行 | Craft 模式的 shell/文件操作全部在一次性沙箱内执行，网络出口白名单，执行完即销毁 |
| F5.4 | 数据防泄漏 | 知识库/文件按权限检索（检索前过滤而非检索后过滤）；提示词注入检测 |
| F5.5 | 内容审计 | 对 Agent 输入输出做敏感词/合规扫描，支持企业自定义规则 |

### M6 协作（P1，对标"项目空间"）

| 编号 | 需求 | 说明 |
|---|---|---|
| F6.1 | 项目空间 | 项目 = 成员 + 共享知识库 + 共享记忆 + 任务看板 + 产物库 |
| F6.2 | 任务分配与进度 | 管理员把任务派给某成员或其 Agent，看板可视化进度 |
| F6.3 | 评论与验收 | 产物上评论、@AI 按评论逐条修改（复用人机双写链路） |

### M7 管理后台与运维（P1）

| 编号 | 需求 | 说明 |
|---|---|---|
| F7.1 | 租户/用量管理 | 租户开通、模型额度、调用量统计、成本分摊报表 |
| F7.2 | 可观测性 | 补 nanobot 短板（社区自己承认 observability 必须加强）：全链路 Trace、Token 成本、工具调用成功率、Langfuse 集成 |
| F7.3 | 监控告警 | 渠道掉线、队列积压、模型失败率超阈值告警 |

## 4. 核心数据模型（简化）

```
Tenant 1─n User n─n Role
Tenant 1─n AgentInstance（= nanobot 实例：模型+工具+记忆命名空间）
AgentInstance 1─n Expert（专家 ≈ AgentInstance + 知识库 + 提示词）
Expert n─n Skill（版本化）
User/Department 1─n ChannelBinding（IM 账号绑定）
Project 1─n Task 1─n TaskRun 1─n StepTrace 1─n Artifact
TaskRun 1─n Approval（待审批动作）
KnowledgeBase 1─n Document（向量索引 + 权限标签）
MemoryEntry（tenant_id, user_id, scope, content, dream 合并状态）
AuditLog（不可变，append-only）
```

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | IM 指令首响应 ≤3s（排队除外）；长任务支持小时级运行 |
| 可用性 | 私有化交付 99.9%；引擎无状态化可水平扩展 |
| 安全 | 等保二级对齐；密钥 KMS 管理；审计日志防篡改 |
| 合规 | 记忆可导出/删除；不出租户边界；支持完全离线部署（内网 vLLM） |
| 成本 | 单次普通任务 Token 成本可核算到租户/用户 |

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| nanobot 迭代快、API 不稳 | 依赖引入 + 防腐层（Adapter）隔离引擎接口，升级只改 Adapter；锁定版本 |
| Python 引擎性能天花板 | 重活外移：沙箱执行、队列、检索都用 Go/独立服务，nanobot 只做编排和对话 |
| 个人微信接入合规风险 | 只走企业微信/飞书/钉钉官方机器人接口，不接个人号协议 |
| 沙箱逃逸与越权 | 执行层独立部署、gVisor 级隔离、网络默认拒绝、工具调用二次鉴权（引擎层白名单 + 平台层审批双层） |
| 记忆合规（个保法） | 记忆用户可见可删、按租户物理隔离、Dream 自动合并的产物需用户可审查 |
| 与 WorkBuddy 正面竞争 | 不拼 C 端体验，拼"可私有化 + 数据主权 + 引擎可控"，打 WorkBuddy 覆盖不到的内网/政企市场 |
