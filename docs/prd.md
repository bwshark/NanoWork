# 产品需求文档（PRD）— 类 WorkBuddy 智能体客户端助手（基于 nanobot 引擎）

> 文档状态：初版 / 简单 PRD（默认格式）
> 产品经理：许清楚（Xu）
> 主理人：齐活林（team-lead）
> 参考引擎：nanobot（HKUDS）｜对标形态：WorkBuddy
> 技术栈（默认）：Vite + React + MUI + Tailwind CSS（渲染层）；Electron（桌面外壳）；后端直连 nanobot OpenAI 兼容 API

---

## 1. 产品目标

**一句话定位**
一款基于 nanobot 引擎、跨端（Electron 桌面 + Web 浏览器同一 React 渲染层）的智能体客户端助手，提供多 Agent 流式会话、技能/MCP/定时任务管理与富产物渲染，始终直连 nanobot 网关，连接状态实时探测。

**核心目标（5 条）**
- **G1 跨端一致体验**：同一套 React 渲染层既可在浏览器运行，也可被 Electron 主进程加载为桌面应用，功能与数据模型一致。
- **G2 引擎即插即用**：直连 nanobot 网关（OpenAI 兼容 API，可配置 endpoint + token/apiToken），连接状态实时探测（connected / offline）并在 UI 中清晰展示。
- **G3 可视化 Agent 运维**：在客户端 UI 中可视化地管理多 Agent、技能（Expert Kits）、MCP 服务、定时任务，降低 nanobot 运行时使用门槛。
- **G4 安全可控**：对文件读写、终端命令、网络访问等敏感操作执行权限门控（确认弹窗），用户可批准/拒绝并记录。
- **G5 长任务协作体验**：富产物渲染（HTML/SVG/图像/视频/Mermaid/代码/文档）+ 本地持久化，支撑 Desktop Cowork 类长任务。

## 3. 需求池（P0 / P1 / P2 分级）

> 优先级：P0 = 必须有（首版 MVP）；P1 = 应该有（首版或紧随其后）；P2 = 锦上添花（后续迭代）。
> 验收标准中「必须/应该/可以」遵循 RFC 2119 语义。

### P0 — 必须有

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|------|------|------|--------|----------|
| FR-001 | 多 Agent 流式会话 | 在会话页支持创建/切换多个 Agent 会话，调用 nanobot OpenAI 兼容流式补全 API 接收消息与工具输出日志。 | P0 | 必须能创建会话、选择 Agent、流式显示回复与工具调用过程；断流可重试。 |
| FR-002 | Agent 管理 UI | 列表/增删改/启用停用自定义 Agent（名称、系统身份提示、模型、绑定技能、工作目录、IM 绑定开关）。 | P0 | 必须支持完整 CRUD 并持久化；所选 Agent 必须能作为当前会话目标。 |
| FR-003 | 技能（Expert Kits）管理 UI | 展示内置技能目录，支持启用/停用与能力说明查看。 | P0 | 必须能查看技能列表并切换启用状态，状态必须持久化。 |
| FR-004 | MCP 服务管理 UI | 添加/编辑/删除 MCP Server（名称、传输类型 URL/命令、认证信息），并可同步到 nanobot 运行时。 | P0 | 必须支持 CRUD 与连接状态显示；保存后应在运行时可见。 |
| FR-005 | 定时任务管理 UI | 通过 UI 创建/查看/启停周期任务（cron/间隔、触发提示、目标 Agent）。 | P0 | 必须能创建任务并在列表显示；必须能启停与删除。 |
| FR-006 | 设置：网关配置与连接探测 | 配置 endpoint + apiToken/key；保存后重新探测网关可达性（connected / offline）并展示状态。 | P0 | 保存后连接必须生效；状态横幅必须实时反映 connected / offline。 |
| FR-007 | 富产物渲染 | 会话内渲染 HTML/SVG/图像/视频/Mermaid/代码/MD/文档，提供预览与下载。 | P0 | 常见类型必须正确渲染，代码应高亮，产物可下载。 |
| FR-008 | 本地持久化 | 桌面用 Electron 持久化，Web 用 localStorage/IndexedDB，保存会话、Agent 配置、技能/MCP/任务配置。 | P0 | 重启应用后数据必须仍然存在且一致。 |
| FR-009 | 敏感操作权限门控 | 文件读写、终端、网络等工具调用前弹出确认弹窗，允许/拒绝并记录决策。 | P0 | 敏感工具调用必须触发确认；拒绝时必须不执行该步。 |

### P1 — 应该有

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|------|------|------|--------|----------|
| FR-010 | IM 远程控制 | 绑定微信/飞书/Telegram 等渠道，远程触发桌面 Agent 执行任务。 | P1 | 绑定后应通过 IM 消息成功发起并收到结果（依赖 nanobot channel 能力）。 |
| FR-011 | 工作区文件记忆 | 读写 MEMORY.md / USER.md / 日记作为长期记忆，注入会话上下文。 | P1 | 必须可编辑并在会话中生效；变更应持久化。 |
| FR-012 | 对话创建定时任务 | 在会话中通过自然语言创建/管理周期任务。 | P1 | 应能从对话意图生成任务并进入任务列表。 |

### P2 — 锦上添花

| 编号 | 名称 | 描述 | 优先级 | 验收标准 |
|------|------|------|--------|----------|
| FR-013 | 托盘 / 通知 | 桌面最小化到托盘、任务完成系统通知。 | P2 | 可以常驻托盘并弹出完成通知。 |
| FR-014 | 产物库管理 | 跨会话归档/检索富产物。 | P2 | 可以在产物库查看历史产物并检索。 |
| FR-015 | 多模型/供应商切换 | 每个 Agent 可选不同模型供应商与参数。 | P2 | 可以为 Agent 指定模型并生效。 |

## 4. UI 设计稿（文字版）

### 4.1 路由与页面

| 路由 | 页面 | 核心元素与交互 |
|------|------|----------------|
| `/chat` | 会话页 | 左侧 Agent/会话列表；主区消息流（用户/Assistant/工具调用卡片）；底部输入框 + 模型/Agent 选择；工具调用卡片可展开看参数与结果；敏感操作触发确认弹窗；产物内联渲染。 |
| `/agents` | Agent 管理 | 卡片/表格列表；新建/编辑抽屉（身份、模型、技能多选、工作目录、IM 绑定）；启用/停用开关；删除确认。 |
| `/skills` | 技能市场 | 技能网格（图标、名称、简介、启用开关）；点击查看能力详情；搜索/筛选。 |
| `/mcp` | MCP 管理 | 列表 + 新增表单（名称、传输类型、地址/命令、认证）；连接测试按钮；同步状态标签。 |
| `/tasks` | 定时任务 | 列表（名称、调度、目标 Agent、状态）；新建（cron/间隔、提示词、Agent）；启停/编辑/删除。 |
| `/settings` | 设置 | 网关 endpoint、apiToken/key 输入；记忆开关（注入/自动沉淀）；关于/数据管理（清空本地数据）。 |
| `/artifacts` | 产物库（P2） | 按会话/时间归档的富产物卡片；点击预览、下载、检索。 |

### 4.2 组件树（以会话页为例）

```
AppLayout
├─ SidebarNav            (导航：会话/Agent/技能/MCP/任务/设置)
├─ ChatPage
│  ├─ SessionListPanel   (多 Agent 会话列表，新建/切换/删除)
│  ├─ ChatHeader         (当前 Agent 名称/模型/状态)
│  ├─ MessageStream
│  │  ├─ UserMessage
│  │  ├─ AssistantMessage (流式渲染，markdown)
│  │  ├─ ToolCallCard     (参数/结果可展开)
│  │  └─ ArtifactRenderer (HTML/SVG/图/视频/Mermaid/代码/MD)
│  ├─ PermissionDialog   (敏感操作确认弹窗)
│  └─ Composer           (输入框 + Agent/模型选择 + 发送)
└─ Toast/Notification
```

### 4.3 共享组件
- `ArtifactRenderer`：按产物类型分发渲染（代码高亮、Mermaid 解析、iframe 预览、图片/视频标签）。
- `ConfirmDialog`：通用确认（删除、敏感操作）。
- `ConnectionBanner`：顶部横幅显示当前连接状态（已连接 / 离线）。

## 5. 待确认问题（含推荐默认）

| # | 待确认点 | 推荐默认 | 理由 |
|---|----------|----------|------|
| Q1 | 首版是否实现 IM 远程控制（FR-010）？ | **首版仅预留接口，不实现 UI**；nanobot 已支持渠道，后续接入。 | 复杂度高、依赖外部账号，先聚焦客户端核心闭环。 |
| Q3 | Electron 持久化用 SQLite 还是 JSON 文件？ | **SQLite（better-sqlite3）**，与 WorkBuddy 对齐；Web 用 IndexedDB。若图开发速度，首版可用 JSON 文件过渡。 | 结构化查询与扩展性更好；JSON 上手快但难扩展。 |
| Q4 | 富产物中视频/复杂文档生成首版是否支持？ | 首版支持 HTML/SVG/图像/Mermaid/代码/MD；视频仅外链预览，本地生成留 P2。 | 控制首版范围，Mermaid/代码/HTML 覆盖大多数演示。 |
| Q5 | 是否需要用户登录/多用户账号体系？ | 首版**单机单用户**，不做账号。 | 个人自托管定位，降低首版成本。 |
| Q6 | 桌面与 Web 的打包/构建方式？ | 共享 React 渲染层，Electron 外壳 + Web 静态构建**分离打包**。 | 一套代码双端，避免耦合。 |
| Q7 | 流式走 nanobot 的 WebSocket 还是 OpenAI 兼容 API？ | 首版走 **OpenAI 兼容流式补全 API**（简单稳定）；WebSocket 作为后续增强。 | API 形态成熟，优先打通主链路。 |

## 附：范围边界（明确不做）
- 不重写智能体引擎（复用 nanobot 小代理循环 / 记忆 / 技能 / 多代理委派）。
- 首版不实现账号体系、多租户、团队协作后端。
- 首版不实现 IM 远程控制 UI（仅预留）。
