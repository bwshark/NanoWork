## 2. 唯一真实候选增强（设计级，需单独规格 + 用户裁决）

**问题**：`identityFiles` / `promptOverrides` 是**文件级 LWW**（6b 设计：整体是一份文档，无稳定段）。
两台设备**并发编辑同一身份文件**（各自的 `rev`/`updatedAt` 不同步推进）时，LWW 三级 tie-break 取
「最新写者胜」，落败一方的编辑**静默丢失**——记忆是段落级并集（安全），但身份文件/提示词是整体覆盖
（有损）。

**候选方案（未实现，待裁决）**：
- A. **维持现状**：身份文件本就「单点真理」，用户通常在单设备改；并发编辑概率低，丢失可接受。
- B. **文件级 3-way merge**：以「同步服务端已知版本」为 base，两端相对 base 做行级合并；复杂度高，
  且身份文件是 Markdown 自由文本，行级合并可能产生语义冲突。
- C. **加「冲突快照」**：落败方写入 `sync-conflicts.json`（已有基础设施，见 6a D-13），由用户手动取舍，
  不自动覆盖。复用既有 `conflict` 通道，改动最小。

**裁定**：本批**不改代码**。候选方案 C 改动最小且复用既有通道，若用户选中，再立独立规格落地
（判据：冲突时 `sync-conflicts` 出现条目、UI 可查看、手动采纳/丢弃）。
