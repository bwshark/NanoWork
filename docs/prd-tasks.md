# 增量 PRD：对话创建定时任务（从消息一键建任务）

> 本文件为 `docs/prd.md`（P0）与 `docs/prd-memory.md`（记忆）的增量补充，仅描述「**从一段对话/某条消息一键创建定时任务**」这一入口变更，不重写既有任务 CRUD / 记忆需求。
> 对应 OVERVIEW.md 后续建议 #3 中的「对话创建定时任务」（原 FR-012，本次落地为 P0 增量入口）。
> 产品经理：许清楚（Xu）｜ 关联：复用 `tasksStore.addTask` 与 `TasksPage` 表单字段语义，不新增任务数据结构。

## 1. 需求目标与价值
让用户在聊天流中选中某条消息（尤其 assistant 产出或 user 诉求），hover 即见「⏰ 创建定时任务」，点开后弹出**预填**对话框（提示词自动取该消息全文、目标 Agent 取当前会话 `session.agentId`、名称按消息首行自动生成），确认后直接写入 `tasksStore`，与现有「定时任务」页（FR-005）完全打通。把"把这条内容以后定期跑"的意图从"切到任务页手填"降为一键，复用已建成的调度引擎，无需新造数据结构，闭环轻、价值高。

## 2. 用户故事
- **US-T1（从 assistant 消息）**：As a 用户, I want 在 assistant 某条产出（如日报/监控结论）上 hover 点「⏰ 创建定时任务」并确认调度, so that 它每天自动按此提示词重跑，无需去任务页手填。
- **US-T2（从 user 消息）**：As a 用户, I want 在我提过的一句诉求（如"每周一把竞品动态汇总给我"）上直接建任务, so that 我的意图被固化成周期任务而不丢失。
- **US-T3（创建后管理）**：As a 用户, I want 创建后在「定时任务」页看到刚建的任务并可启停/编辑/删除, so that 入口与既有管理页是同一套数据，无割裂。

## 3. 需求池
### P0 — 必须有
- **FT-01 消息 hover 操作**：`AssistantMessage` 与 `UserMessage` 均增加 hover 操作行，含「⏰ 创建定时任务」按钮（`IconButton` + `Tooltip`，复用现有 hover 渐显逻辑 `opacity`/`pointerEvents`），与已有「💾 保存为记忆」按钮并排。`UserMessage` 已备 memory 按钮；`AssistantMessage` 须补同等 hover 行（本次一并加 task 按钮，memory 按钮是否同步补入见 Q4）。
- **FT-02 预填对话框 `CreateTaskDialog`**：复用 `TasksPage` 现有字段与语义——任务名称、调度类型（`interval`/`cron`）、间隔分钟数 / Cron 表达式、目标 Agent、触发提示词（多行）。预填规则：**提示词=`message.content`**；**目标 Agent=`session.agentId`**（空则回退 `agents[0]?.id`，如 `TasksPage.openNew`）；**名称=消息首行截断≤20字**（可改）。
- **FT-03 保存闭环**：确认→`tasksStore.addTask({name,prompt,agentId,schedule})`→`toast.success('已创建定时任务')`→关闭对话框。不重复实现 CRUD，仅此单入口写入。
- **FT-04 与 TasksPage 共享表单**：将 `TasksPage` 内联对话框抽为共享组件 `src/components/tasks/TaskFormDialog.tsx`（受控 `initial` + `onSubmit`），`TasksPage` 与聊天入口共同挂载，保证字段/校验（名称非空）完全一致。

### P1 — 应该有
- **FT-05**：创建后可选 toast 附带「在定时任务页管理」按钮（跳转 `/tasks`）；对话框支持"保存并继续建下一个"。
- **FT-06**：从 user 消息建任务时，若 `session.agentId` 为空给出 Agent 必选提示。

### P2 — 锦上添花
- **FT-07**：支持选中消息内**文本片段**（而非整条）作为提示词预填。
- **FT-08**：基于消息语义自动推荐调度类型（如含"每天/每周"→cron 草拟）。

## 4. UI / 交互要点
消息 hover 操作行（与「💾 保存为记忆」并排，角标对齐消息侧）：
```
AssistantMessage（左）                 UserMessage（右）
┌─────────────────────────┐           ┌─────────────────────────┐
│ [💾] [⏰]  ← hover 行     │           │     [💾] [⏰] ← hover 行 │
│ ┌─────────────────────┐ │           │         ┌─────────────┐ │
│ │ Markdown 内容…      │ │           │         │ 用户气泡…  │ │
│ └─────────────────────┘ │           │         └─────────────┘ │
└─────────────────────────┘           └─────────────────────────┘

点击 ⏰ → CreateTaskDialog（复用 TasksPage 字段，已预填）
┌─ 创建定时任务（来自对话）─────────────┐
│ 任务名称：[每周竞品动态汇总_]         │
│ 调度类型：[间隔(分钟)▾] 间隔分钟数[60]│
│ 目标 Agent：[当前会话 Agent▾]         │
│ 触发提示词（已预填消息全文）：         │
│  ┌──────────────────────────────┐   │
│  │ 每周一把竞品动态汇总给我…    │   │
│  └──────────────────────────────┘   │
│              [取消]  [创建任务]       │
└────────────────────────────────────┘
```
交互：hover 显示双按钮；点 ⏰ 弹 Dialog（标题"创建定时任务（来自对话）"以区分新建）；保存走 `addTask`，校验同 TasksPage（名称非空才可点"创建任务"）；成功 toast 后留在聊天页。

## 5. 待确认问题（含推荐默认）
1. **支持选中文本片段而非整条消息？** 推荐默认**整条消息**；片段选入留 P2（FT-07）。理由：实现简单、覆盖绝大多数场景。
2. **创建后是否跳转 `/tasks`？** 推荐默认**不跳转**，仅 `toast.success`；可附带「去管理」按钮（FT-05）。理由：不打断对话流。
3. **`agentId` 是否必填校验？** 推荐**必填**；预填 `session.agentId`，为空时退回 `agents[0]?.id` 并高亮提示（FT-06）。理由：空 Agent 任务无法触发，等同废单。
4. **`AssistantMessage` 是否同步补「💾 保存为记忆」按钮？** 推荐**本次一并补上**，与本增量 hover 行统一（记忆 PRD 仅描述菜单，未强制 assistant 侧）。理由：操作一致性，工作量极小。
5. **名称自动生成规则** 推荐：取首行 `trim` 截断 20 字，超长加「…」；用户可编辑。理由：够用且不遮挡。
