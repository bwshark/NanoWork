综合 WorkBuddy 官方文档与本地文件/社区拆解，可以把它理解成：**“分层持久化 + 定时提炼写入 + 会话启动注入 + 自然语言/文件治理”** 的混合记忆机制，而不是单纯把聊天记录存起来。

| 层级 | 典型位置/载体 | 记录内容 | 生效范围 | 实现要点 |
|---|---|---|---|---|
| 会话上下文 | 当前对话窗口 | 本轮任务细节 | 仅当前会话 | 关窗即失；本轮优先级最高，但不是长期记忆 |
| 云端画像/对话记忆 | 服务端生成，本地 `~/.workbuddy/memory/` 多为缓存镜像 | 职业、偏好、习惯、近期关注等稳定事实 | 跨设备、跨会话 | 官方口径是默认开启，从历史会话提取“有参考价值”的个人信息并定期更新，后续对话作为背景参考。 |
| 用户级本地记忆 | `~/.workbuddy/MEMORY.md` | 跨项目通用规则、表达偏好、硬性约束 | 所有项目 | 可用自然语言让 WorkBuddy 记住/更改/删除；每次新会话会合并进提示词，因此建议控制数量，避免挤占上下文。 |
| 项目级工作区记忆 | `<项目>/.workbuddy/memory/MEMORY.md`、`<项目>/.workbuddy/memory/YYYY-MM-DD.md` | 项目约定、技术选型、架构决策、踩坑记录、每日工作日志 | 仅当前项目 | 每日日志 append-only；完成实质工作后追加当日记录，稳定结论沉淀到 `MEMORY.md`。 |
| 人格/身份文件 | `.workbuddy/SOUL.md`、`IDENTITY.md`、`USER.md` 等 | 助手人格、身份、用户背景 | 项目/工作区 | 更偏“ persona + 用户档案”，在会话启动或初始化时读取，帮助保持一致风格与边界。 |
| 技能与自动化 | `~/.workbuddy/skills/`、`<项目>/.workbuddy/skills/`、`~/.workbuddy/workbuddy.db` | 可复用流程、周期/一次性任务状态 | 用户级或项目级 | 技能把多步操作经验固化为可复用模块；自动化任务状态和运行历史持久化，接近“时间维度上的记忆”。 |

写入链路大致是：

1. **判断值不值得记**：不是全量保存聊天原文；官方描述是提取事实信息、偏好习惯、人物关系、近期跟进事项等，并在后续请求相关时作为背景参考。  
2. **分层落盘**：项目过程写 `YYYY-MM-DD.md`；项目长期规则写项目 `MEMORY.md`；跨项目偏好写用户级 `MEMORY.md`；稳定用户画像由服务端维护。第三方拆解称云端画像会在会话启动时以 `<memory>...</memory>` 块注入系统提示，AI 可读但不应本地篡改，因为本地缓存会被服务端同步覆盖。  
3. **读取链路**：新会话开始时注入云端画像 + 用户级记忆；进入项目工作区再加载项目记忆；当前对话上下文仍然优先级最高。  
4. **更新与遗忘**：支持查看、编辑、删除或关闭；记忆摘要官方称“每晚重新生成”。重要规则如果只停留在口头对话，可能被后续上下文覆盖或蒸馏压缩掉；所以关键约束应明确“写进 MEMORY.md”。

它和普通“聊天记录搜索”的区别在于：记忆被设计成**主动注入的默认上下文**，而不是等你去翻历史；同时用作用域隔离避免 A 项目规则污染 B 项目。代价是你要治理它：项目专属规则放项目级，跨项目偏好才放用户级；过期记忆定期清；云端画像本地缓存不要手改，走设置页或自然语言指令维护。
